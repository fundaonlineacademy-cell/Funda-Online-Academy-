# Professional Certificate in Bookkeeping
## Module 7: Computerised Bookkeeping & QuickBooks Fundamentals
### Lesson 6: Correcting Transactions, Audit Trails and User Controls

**Estimated study time:** 50–55 minutes

## Learning Outcomes
By the end of this lesson, you should be able to:
1. Correct computerised bookkeeping errors without destroying traceability.
2. Distinguish edit, void, reversal and correcting-entry approaches.
3. Use audit history to investigate transaction changes.
4. Explain why individual user accounts and permissions matter.
5. Apply period-lock and approval controls to historical changes.

## Why This Lesson Matters
Software makes correcting errors easy, but uncontrolled changes can rewrite history. Professional bookkeeping balances the need to fix mistakes with the need to preserve a reliable audit trail showing what changed, who changed it and why.

## Key Terms
- **Edit** — Change to an existing transaction where the system and policy permit it.
- **Void** — System action retaining a transaction record while cancelling its accounting effect, depending on software behaviour.
- **Reversal** — Opposite accounting entry used to cancel a prior posting.
- **Audit history** — System record of user activity and transaction changes.
- **Period lock** — Control restricting changes to closed accounting periods.
- **User permission** — System right defining allowed actions.

## Main Lesson Content
### 1. Correct the cause, not only the report
If an expense is in the wrong account, trace the source transaction. Do not create unrelated entries simply to make a report look right.

### 2. Choose the approved correction method
The correct method depends on transaction type, period status and software design. Options may include editing an open-period draft, issuing a credit note, voiding, reversing or posting a correcting journal.

### 3. Preserve the original story
Where the transaction was already approved, sent externally, reconciled or included in a closed period, direct editing may be inappropriate. Use the system's controlled correction method.

### 4. Audit history
System history can show who created a transaction, original values, later changes, dates and status changes. This supports review and accountability.

### 5. Individual user accounts
When users operate under their own accounts, transaction history is more reliable and access can be aligned to job responsibilities.

### 6. Permission design
Sensitive rights may include creating suppliers, changing master data, posting journals, deleting transactions, reopening periods or viewing confidential reports. Access should follow the organisation's approved role design.

### 7. Closed periods
Historical changes can alter previously issued reports and reconciliations. Period locks should be changed only through authorised procedures.

### 8. Correction documentation
Record the error, correct treatment, supporting evidence, approval and transaction reference. For material errors, retain an explanation sufficient for later review.

## Worked Example
A R15,000 supplier bill posted last month to Repairs should have been Equipment. The period is closed and the invoice has already been paid. The bookkeeper follows the approved correction process, such as an authorised reclassification journal, while retaining the original transaction and correction reference.

## Practical Activity
For each error, choose an appropriate correction route and explain why:
1. Draft invoice with wrong description before issue.
2. Paid supplier bill posted to wrong expense account last month.
3. Duplicate customer invoice already issued.
4. Previously reconciled bank transaction later altered.
5. Supplier master information changed without the normal review record.

## Feedback / Explanation
1. Reviewers need to understand the original error and authorised correction.
2. An opposite entry cancelling a prior posting.
3. User actions and transaction changes, depending on the system.
4. Actions can be attributed more reliably and access can be role-based.
5. They can alter previously reported or reconciled results.
6. Examples include supplier creation, master-data changes, journals, deletions and period reopening.
7. Error, evidence, correct treatment, approval and reference.
8. The real error should be corrected at its source rather than hidden elsewhere.

## Key Takeaways
- Correct errors through approved system workflows.
- Preserve transaction history.
- Audit history depends on accountable user access.
- Sensitive permissions should be restricted.
- Historical and closed-period changes need stronger control.
