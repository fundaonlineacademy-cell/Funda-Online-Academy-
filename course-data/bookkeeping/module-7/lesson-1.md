# Professional Certificate in Bookkeeping
## Module 7: Computerised Bookkeeping & QuickBooks Fundamentals
### Lesson 1: Moving from Manual to Computerised Bookkeeping

**Estimated study time:** 45–50 minutes

## Learning Outcomes
By the end of this lesson, you should be able to:
1. Explain how computerised bookkeeping applies the same accounting principles as manual books.
2. Identify benefits and risks of accounting software.
3. Distinguish transaction screens from the underlying double-entry postings.
4. Explain why setup, access and audit trails matter.
5. Use manual bookkeeping knowledge to diagnose software errors.

## Why This Lesson Matters
Accounting software automates posting, totals, reports and many routine controls, but it does not remove the need to understand bookkeeping. A wrong supplier, date, VAT code or account can be processed instantly and consistently—making an error faster rather than preventing it.

## Key Terms
- **Computerised bookkeeping** — Recording and processing accounting information using software.
- **Transaction module** — Software area for activities such as sales, purchases or banking.
- **Audit trail** — System history showing transactions, users and changes.
- **User role** — Access level defining what a person may view or change.
- **Integration** — Automated transfer of information between system areas or connected services.
- **Backup/export** — Controlled copy or extract used for continuity, reporting or evidence.

## Main Lesson Content
### 1. The principles do not change
A sales invoice may be entered through a customer screen, but the system still creates accounting effects such as Debtors and Sales. A supplier payment still reduces Bank and Creditors.

### 2. Benefits of software
Common benefits include faster posting, automatic calculations, search, document attachment, real-time reports, bank feeds, customer/supplier statements and user audit trails.

### 3. Risks of automation
Software can repeat bad setup. If an expense account is mapped incorrectly, hundreds of transactions may be classified wrongly. Automation should therefore be reviewed, not blindly trusted.

### 4. Transaction screens versus journals
Modern software often hides debit-credit language behind forms. Bookkeepers should still ask: Which accounts are increasing or decreasing? Is the transaction already recorded? What evidence supports it?

### 5. Master data
Customer names, supplier details, tax settings, account codes and opening balances influence every later transaction. Setup errors can spread widely.

### 6. User access
Not every user should be able to create suppliers, post journals, approve payments and change historical transactions. Apply least-necessary access according to role.

### 7. Audit trail
Individual user accounts help trace who created or changed records. Shared passwords weaken this control.

### 8. Manual knowledge helps troubleshooting
If a report is wrong, trace the accounting flow: source document → transaction screen → ledger account → report. Understanding double entry makes the software easier to diagnose.

### 9. QuickBooks context
QuickBooks is one example of accounting software. Menu names and features can vary by edition and update. This course teaches transferable bookkeeping workflows rather than relying on one screen layout.

## Worked Example
A supplier invoice for R4,000 repairs is entered accidentally to Office Equipment. The software posts perfectly—but to the wrong account. The trial balance still balances. The bookkeeper finds the error by reviewing the source invoice and account detail, then uses the authorised correction workflow.

## Feedback / Explanation
1. No. The same accounting logic operates underneath the software.
2. Examples: faster posting, search, automatic reports, statements, bank feeds and audit trails.
3. A wrong rule can be applied repeatedly across many transactions.
4. Core records/settings such as customers, suppliers, accounts and tax configuration.
5. To limit error, fraud and inappropriate changes.
6. Traceability of transactions and changes by users.
7. It helps identify which accounting step or account is wrong.
8. Software interfaces change; bookkeeping principles and control workflows are more transferable.

## Key Takeaways
- Software automates bookkeeping; it does not replace bookkeeping knowledge.
- Master data and setup quality are critical.
- Access and audit trails are core controls.
- Automated transactions still require evidence and review.
- Transferable accounting logic matters more than memorising buttons.
