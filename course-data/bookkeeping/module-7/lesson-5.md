# Professional Certificate in Bookkeeping
## Module 7: Computerised Bookkeeping & QuickBooks Fundamentals
### Lesson 5: Banking, Bank Feeds and Reconciliation Workflows

**Estimated study time:** 50–55 minutes

## Learning Outcomes
By the end of this lesson, you should be able to:
1. Explain how bank feeds support transaction matching and capture.
2. Distinguish matching an existing transaction from creating a new one.
3. Categorise imported bank items carefully.
4. Prepare a software-based bank reconciliation.
5. Identify common bank-feed and reconciliation errors.

## Why This Lesson Matters
Bank feeds reduce manual data entry by importing transactions from the bank. They improve speed but can create duplicates when the bookkeeper adds an imported payment that was already captured through a supplier, customer or expense workflow.

## Key Terms
- **Bank feed** — Imported electronic stream of bank transactions.
- **Match** — Linking an imported bank item to an existing accounting transaction.
- **Add/Categorise** — Creating a new accounting transaction from an imported bank item where appropriate.
- **Reconciliation screen** — Software workflow comparing book transactions to a bank statement.
- **Opening reconciliation balance** — Prior reconciled balance carried into the next reconciliation.

## Main Lesson Content
### 1. Imported does not mean recorded correctly
A bank-feed line is evidence of a bank movement. It still needs matching or classification.

### 2. Match existing items
If a supplier payment was already created in Accounts Payable, match the bank-feed withdrawal to that payment. Adding it as a new expense would duplicate the cash movement and expense.

### 3. Add genuinely new items
Some statement-driven items such as bank charges or interest may first appear in the feed. These can be added to the correct accounts with appropriate evidence and review.

### 4. Customer receipts
Match customer receipts to recorded invoices/payments when possible. Do not classify an unknown deposit as Sales until its source is confirmed.

### 5. Rules and automation
Some systems allow bank rules that automatically suggest categories. Review rules periodically; a broad rule can misclassify new transaction types.

### 6. Reconciliation workflow
A software reconciliation normally requires:
- statement ending date;
- statement closing balance;
- matching cleared receipts/payments;
- identifying outstanding items;
- investigating differences;
- completing only when supported.

### 7. Opening-balance problems
If a prior reconciliation was changed after completion, the next opening balance may differ. Use audit/history reports to find deleted, changed or unreconciled historical transactions.

### 8. Never force the difference
Do not create a random adjustment merely to make the reconciliation screen reach zero. Investigate transaction changes, duplicates, omissions and statement cut-off.

## Worked Example
A R7,500 supplier EFT already exists in the software as a payment. The bank feed imports the same R7,500 withdrawal. If the bookkeeper adds it to Repairs Expense, the books show two bank reductions. Correct action: match the imported line to the existing supplier payment.

## Practical Activity
Classify eight bank-feed lines as Match, Add, Investigate or Escalate. Include a known supplier EFT, bank fee, unidentified deposit, card settlement, changed supplier payment, duplicate amount and reversed debit order.

2. What is the difference between Match and Add?
3. Why can bank rules create risk?
4. How should an unknown deposit be handled?
5. What information starts a reconciliation?
6. What can cause an opening-balance difference?
7. Why should the reconciliation not be forced?
8. What should happen with bank charges first discovered in the feed?

## Feedback / Explanation
1. Electronic import of banking transactions.
2. Match links to an existing entry; Add creates a new accounting transaction.
3. Broad or outdated rules can repeatedly misclassify transactions.
4. Investigate before allocation.
5. Correct statement period and closing balance plus book transaction data.
6. Changes to previously reconciled transactions are a common cause.
7. A forced adjustment can hide the real error.
8. Capture to the appropriate account after verification.

## Key Takeaways
- Bank feeds automate data movement, not accounting judgement.
- Match existing transactions whenever they already exist.
- Automation rules need review.
- Reconciliation differences require investigation.
- Historical changes can disrupt future opening balances.
