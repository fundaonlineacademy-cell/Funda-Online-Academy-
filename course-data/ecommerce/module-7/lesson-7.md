# E-commerce & Online Store
## Module 7: Online Security & Fraud Awareness
### Lesson 7: Device, Website & Administrator Security

**Estimated study time:** 35–40 minutes

## Learning Outcomes
By the end of this lesson, you should be able to:
1. Explain why endpoint and administrator security affect the online store.
2. Identify basic controls for devices and store administration.
3. Explain the importance of software updates and trusted integrations.
4. Apply safe backup and recovery principles.
5. Recognise when technical changes require authorised review.

## Why This Lesson Matters
A secure online store can still be compromised through an infected laptop, an outdated plugin, an abandoned administrator account or an unsafe third-party integration. Security therefore extends beyond the storefront itself. Staff should understand the basic controls that keep the systems used to manage the store trustworthy.

## Key Terms / Vocabulary
- **Endpoint** — A device such as a laptop or phone used to access business systems.
- **Patch/update** — A software change that may correct vulnerabilities or improve security.
- **Administrator account** — An account with elevated control over systems or settings.
- **Integration** — A connection between the store and another service.
- **Backup** — A separate copy of data or configuration used for recovery.
- **Recovery** — Restoring systems or information after failure or incident.

## Main Lesson Content
### 1. Protect devices used for administration
Business devices should use supported operating systems, screen locks, updated software and approved security controls. Store administration should not be performed casually from unknown or untrusted devices.

### 2. Keep systems updated
Outdated store software, plugins or extensions can contain known vulnerabilities. Updates should be tested and applied through a controlled process, especially for components that affect checkout or customer data.

### 3. Limit administrator access
Only people who genuinely need administrator rights should have them. Day-to-day tasks should use lower-risk permissions where possible. Old accounts should be removed and access reviews performed regularly.

### 4. Review third-party integrations
Apps, plugins and services can receive access to product, order or customer data. The business should understand why an integration is needed, what permissions it requests and whether the provider is trustworthy. Unused integrations should be removed.

### 5. Maintain backups and recovery capability
Backups should be stored separately enough that one failure does not destroy both the live system and recovery copy. The business should know what is backed up, how often, and how restoration would work. A backup that has never been tested may fail when needed most.

### 6. Control technical changes
Changes to payment settings, DNS, checkout scripts, administrator roles or integrations should be authorised and documented. Unexpected technical changes may indicate error or compromise and should be investigated.

## Worked Example / Demonstration
A store owner installs an unknown discount plugin using a full administrator account. The plugin requests broad access to customer and order data. Before activation, the owner should review whether the plugin is necessary, its provider reputation, requested permissions and safer alternatives rather than granting access automatically.

## Practical Activity
Create a monthly store-security checklist covering devices, updates, administrator accounts, integrations, backups and unexpected configuration changes.

## Knowledge Check

4. What should be reviewed before installing an integration?
5. Why should backups be tested?

## Feedback / Explanation
1. A device used to access systems.
2. They may correct known security weaknesses.
3. Elevated access creates greater risk if compromised.
4. Purpose, permissions, provider trust and necessity.
5. A backup is useful only if it can be restored successfully.

## Key Takeaways
- Store security depends on secure devices and administrator accounts.
- Software and integrations should be managed deliberately.
- Excessive permissions create unnecessary risk.
- Backups support recovery from incidents and failures.
- High-risk technical changes should be controlled and documented.
