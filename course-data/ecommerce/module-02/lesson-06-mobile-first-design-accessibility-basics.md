# E-commerce & Online Store
## Module 2: Online Store Planning, Platforms & Setup
### Lesson 6: Mobile-first Design & Accessibility Basics

**Estimated Study Time:** 40–45 minutes

## Learning Outcomes
By the end of this lesson, the learner should be able to:
1. Explain why an online store must work effectively on mobile devices.
2. Apply basic mobile-first principles to store navigation, product pages and checkout.
3. Identify common barriers that make websites difficult to use for people with disabilities.
4. Recommend practical accessibility improvements involving text, images, forms, controls and keyboard use.
5. Conduct a basic mobile and accessibility review before launch.

## Why This Lesson Matters
Customers may visit an online store using phones, tablets, laptops, assistive technologies or different network conditions. A store that looks attractive on a large desktop screen can become difficult to use when controls are crowded, text is tiny, images are heavy or forms are hard to complete on a phone. Accessibility also matters because customers have different visual, hearing, motor and cognitive needs. Designing for a wider range of users improves professionalism, usability and customer reach.

## Key Terms / Vocabulary
- **Mobile-first design** — Planning the essential experience for smaller screens first, then enhancing it for larger screens.
- **Responsive design** — A design approach in which page layout adapts to different screen sizes and orientations.
- **Accessibility** — Designing digital content and functions so that people with a wide range of abilities can perceive, understand and operate them.
- **Alternative text (alt text)** — Text that describes the purpose or meaningful content of an image for users who cannot see it.
- **Keyboard navigation** — Operating website controls using a keyboard rather than relying only on a mouse or touchscreen.
- **Focus indicator** — A visible sign showing which interactive element is currently selected during keyboard navigation.
- **Contrast** — The visual difference between foreground content, such as text, and its background.
- **Touch target** — An interactive area, such as a button or link, that a touchscreen user must be able to tap accurately.

## Main Lesson Content
### 1. Start with the essential mobile journey
Mobile-first thinking asks what the customer must be able to do on a small screen without unnecessary friction. For an online store, essential tasks usually include opening navigation, searching, viewing products, selecting variants, adding to cart, reviewing the cart, completing checkout and finding support or policy information.

The mobile version should not be treated as a reduced-quality copy of the desktop site. Important information such as price, stock status, delivery expectations and product options must remain understandable. Decorative elements can be simplified, but essential buying information should not disappear merely because the screen is smaller.

### 2. Responsive layouts need deliberate testing
Responsive themes can rearrange columns, menus and images automatically, but automatic behaviour is not proof of good usability. A three-column product grid may become one column on a phone, a desktop menu may become a menu button, and images may resize. The merchant must still check whether headings wrap sensibly, buttons remain easy to tap, pop-ups block content, product options remain visible and checkout forms fit the screen.

Testing should include more than one screen width where possible. Orientation changes, browser zoom and longer text can expose layout problems that are not visible in the store builder's default preview.

### 3. Keep mobile interaction simple
Small screens punish unnecessary complexity. Navigation labels should be concise. Buttons should communicate actions clearly, such as “Add to cart” rather than vague labels. Important controls need sufficient space around them so users do not accidentally tap a neighbouring control. Forms should ask only for information genuinely needed for the transaction or business process.

Performance is also part of the experience. Very large images, excessive scripts, auto-playing media and unnecessary third-party widgets can slow pages, particularly on weaker connections or lower-powered devices. Images should be prepared at suitable dimensions and compressed without destroying the detail needed to evaluate a product.

### 4. Accessibility begins with perceivable information
Customers need to be able to perceive the information presented. Text should be readable, with sufficient size and contrast. Meaning should not depend on colour alone. For example, an error should not be indicated only by changing a field border from grey to red; an explanatory message such as “Enter a valid email address” provides clearer information.

Meaningful product images should have useful alternative text when the image communicates information. Decorative images may not need descriptive alt text. The aim is not to stuff keywords into image descriptions but to communicate relevant purpose or content.

Video used for important instruction should not leave customers who cannot hear the audio without equivalent information. Captions or a useful text alternative can help, depending on the content.

### 5. Controls must be operable
A shopper who cannot use a mouse should still be able to navigate interactive controls. Basic testing can be performed using the Tab key to move through links, fields and buttons. The current element should have a visible focus indicator, and the sequence should be logical. A keyboard user should not become trapped inside a menu, pop-up or widget.

Buttons should be actual understandable controls, not images that merely look like buttons. Form fields need labels that identify what information is required. Placeholder text inside a field should not be the only label if it disappears when the customer starts typing.

### 6. Content should be understandable
Plain, consistent language improves usability for everyone. Use familiar terms such as Cart, Checkout, Delivery and Returns unless there is a strong reason to use something different. Error messages should explain what went wrong and how to correct it. Instructions should appear near the task they relate to.

Consistency matters. If the same icon means “account” on one page, it should not mean something different elsewhere. Prices, product variants and availability should use consistent formats throughout the store.

### 7. Accessibility is an ongoing quality practice
Accessibility should not be treated as a once-off checklist performed after the store is finished. New banners, apps, product media, forms and theme updates can introduce new barriers. The business should include accessibility in routine quality checks.

Automated testing tools can identify some problems, but they cannot determine whether every description is meaningful or whether a checkout journey is understandable. Manual testing remains valuable. Where possible, feedback from people with different access needs provides stronger evidence than assumptions made by the design team.

## Worked Example / Demonstration
A fashion store's mobile product page has a large promotional pop-up covering half the screen. The size selector requires sideways scrolling, the “Add to cart” button sits too close to a wishlist icon, and product colour options are represented only by coloured circles.

A better version could delay or reduce the pop-up, display sizes in a clear responsive control, increase spacing around touch controls, provide text names for colours and verify that the page can be operated by keyboard. Product images should have meaningful descriptions where appropriate, and form errors at checkout should include text explaining the correction required.

## Practical Activity
Review an online store or prototype on a phone-sized screen. Check:
- menu and search usability;
- product title, price and variant visibility;
- button spacing;
- image loading and readability;
- checkout form labels;
- visible error messages;
- text contrast and size;
- keyboard operation on a desktop browser;
- meaningful alternative text where relevant.

Record at least five observations and recommend one improvement for each problem found.

## Knowledge Check
1. What does mobile-first design prioritise?
2. Why is a responsive theme not enough by itself to guarantee good mobile usability?
3. Why should an error not be communicated using colour alone?
4. What is the purpose of a visible keyboard focus indicator?
5. Why should accessibility checks continue after launch?

## Feedback / Explanation
1. It prioritises essential tasks and content for smaller screens before progressively enhancing larger-screen experiences.
2. Automatic resizing cannot determine whether content, controls and complete customer journeys are actually usable.
3. Some users may not perceive the colour difference, so a clear textual or equivalent indicator is needed.
4. It tells a keyboard user which control is currently active or selected.
5. New content, apps, media and updates can introduce accessibility barriers later.

## Key Takeaways
- Mobile customers need the complete essential shopping journey, not a second-class version of the store.
- Responsive design must be tested rather than assumed to work perfectly.
- Readable text, meaningful image alternatives, clear forms and operable controls support accessibility.
- Keyboard testing and realistic mobile task testing can reveal major problems quickly.
- Accessibility and mobile usability should remain part of ongoing store quality assurance.
