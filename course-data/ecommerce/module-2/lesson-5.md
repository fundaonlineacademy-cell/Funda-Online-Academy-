# E-commerce & Online Store
## Module 2: Online Store Planning, Platforms & Setup
### Lesson 5: Product Categories, Collections & Site Search

**Estimated study time:** 40–45 minutes

## Learning Outcomes
By the end of this lesson, you should be able to:
1. Explain the roles of categories, collections, filters and site search.
2. Group products using customer-oriented taxonomy.
3. Identify data-quality problems that weaken search and filtering.
4. Analyse zero-result and irrelevant-result search problems.
5. Design multiple useful discovery paths without creating unnecessary complexity.

## Why This Lesson Matters
A store can have excellent products that customers fail to discover. Product discovery depends on structure and data working together. Categories support browsing, collections support merchandising, filters narrow choices and search responds to customer language. Poor product data weakens all four.

## Key Terms / Vocabulary
- **Category** — A structured grouping of related products.
- **Collection** — A curated group organised around a theme, campaign, season or customer need.
- **Filter** — A control that narrows a set of products using selected characteristics.
- **Taxonomy** — A structured system for classifying products or content.
- **Search query** — Words entered by a customer into site search.
- **Zero-result search** — A query that returns no matching products.
- **Metadata** — Structured information used to describe and organise products.

## Main Lesson Content
### 1. Categories support predictable browsing
Categories should reflect how customers understand the product range. A sports store may use Running, Football and Training rather than supplier-specific internal codes.

Categories should be broad enough to contain meaningful groups but specific enough to help customers narrow choices.

### 2. Collections support merchandising
Collections can group products without changing the permanent taxonomy. Examples include “New Arrivals,” “Winter Essentials,” “Back to School” or “Gifts Under R500.” They are useful for campaigns and seasonal discovery.

### 3. Filters depend on consistent attributes
A size filter works only when product size data is complete and consistent. If colour is recorded as “navy,” “Navy Blue,” “dark blue” and “blue/navy,” filters can fragment results.

Standardised product attributes improve both the customer experience and internal reporting.

### 4. Search depends on language and data
Customers may search by product type, brand, use case, feature or common synonym. Product titles and searchable metadata should contain useful accurate terms without keyword stuffing.

Search configuration may also need synonyms. A South African customer searching “takkies” may be looking for products categorised as sneakers or trainers, depending on the store's audience and search technology.

### 5. Investigate zero-result searches
A zero-result query can mean:
- the business does not stock the item;
- customers use different vocabulary;
- product metadata is incomplete;
- indexing is broken;
- filters are too restrictive.

Analysing these queries can reveal both demand and technical problems.

### 6. Review irrelevant results
Search is also weak when it returns unrelated products. If “running shoes” shows kitchen products, investigate titles, tags, metadata, synonyms and search rules.

### 7. Offer multiple discovery paths
A shopper may reach the same product through a permanent category, a seasonal collection, a search result and a filter. Multiple relevant paths are useful when they remain understandable and consistent.

### 8. Avoid over-classification
Creating a separate category for every SKU produces clutter. Categories should represent meaningful groups, while attributes and filters handle finer distinctions.

### 9. Test with realistic tasks
Test whether customers can find products using common terms and attributes. Include misspellings or synonyms where the search system supports them. Check mobile filters as well as desktop search.

## Worked Example / Demonstration
A fashion store has a filter for size, but many products have size stored only in description text rather than structured fields. Customers selecting “Medium” miss valid products. The solution is not a larger search button; it is consistent catalogue data connected to the filter system.

## Practical Activity
Create a discovery design for 30 imaginary products. Define four categories, three merchandising collections, five filter attributes and ten customer search queries. Identify two synonyms and two zero-result searches you would want the store to analyse.

## Knowledge Check
1. What is the main difference between a category and a collection?
2. Why do filters depend on structured product data?
3. What can zero-result searches reveal?
4. Why can synonyms improve search?
5. Why should a store avoid creating one category for every product?

## Feedback / Explanation
1. Categories provide stable structural classification; collections can create flexible curated groups.
2. Filters need consistent values to include the correct products.
3. Missing products, vocabulary gaps or configuration/data problems.
4. Customers may use different words for the same product.
5. It creates unnecessary complexity and weakens browsing.

## Key Takeaways
- Categories, collections, filters and search solve different discovery problems.
- Customer-facing structure should use understandable language.
- Product data quality directly affects filtering and search.
- Search analytics can reveal demand and catalogue weaknesses.
- Multiple relevant discovery paths can improve product findability.
