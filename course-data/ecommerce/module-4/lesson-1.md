# E-commerce & Online Store
## Module 4: Orders, Payments, Fulfilment & Delivery
### Lesson 1: Order Lifecycle & Order Status Management

**Estimated study time:** 35–40 minutes

## Learning Outcomes
By the end of this lesson, you should be able to:
1. Explain the main stages in an e-commerce order lifecycle.
2. Distinguish between order, payment and fulfilment statuses.
3. Identify risks caused by incorrect order-status handling.
4. Apply a basic order-processing workflow.
5. Escalate exceptions using reliable records.

## Why This Lesson Matters
An online sale does not end when a customer clicks “Place order.” The order must be recorded correctly, payment status must be understood, stock must be allocated, the correct item must be picked and packed, delivery must be arranged and the customer must receive accurate updates. Poor order-status control can cause duplicate fulfilment, unpaid orders being shipped, paid orders being ignored or customers receiving confusing information.

## Key Terms / Vocabulary
- **Order** — A recorded request from a customer to purchase goods or services.
- **Order status** — The current stage of an order, such as pending, confirmed, fulfilled or cancelled.
- **Payment status** — The state of the payment, such as pending, authorised, paid, failed or refunded.
- **Fulfilment status** — The operational stage of preparing and sending the order.
- **Exception** — A problem preventing the normal workflow from continuing.
- **Order number** — A unique reference used to identify an order.

## Main Lesson Content
### 1. Understand the order lifecycle
A typical order moves through several stages: customer submission, order creation, payment verification, stock allocation, picking, packing, dispatch, delivery and completion. Some stores include additional stages such as fraud review, backorder or collection-ready.

The exact labels depend on the platform, but staff must understand what each status means operationally. A status should not be changed simply to make a dashboard look tidy.

### 2. Keep statuses separate
Order status, payment status and fulfilment status answer different questions. An order may exist while payment is still pending. A payment may be successful while fulfilment has not started. A parcel may be dispatched while the order remains open until delivery is confirmed.

Confusing these statuses creates risk. Staff should verify the relevant payment evidence before treating an order as paid and should not mark an order fulfilled before the goods have actually been prepared or handed to the delivery process.

### 3. Use a controlled workflow
A reliable workflow can be:
1. Confirm that the order record is complete.
2. Verify payment status using the approved system.
3. Confirm stock availability and allocate the correct variant.
4. Pick and check the items against the order.
5. Pack and prepare delivery documentation.
6. Dispatch using the selected delivery method.
7. Record tracking or collection information.
8. Close or complete the order only when the required process is finished.

### 4. Manage exceptions
Common exceptions include payment failure, duplicate orders, unavailable stock, incorrect address details, suspicious transactions or customer cancellation requests. Staff should avoid guessing. The exception should be recorded, investigated and escalated when authority is required.

## Worked Example / Demonstration
A customer orders two pairs of shoes. The order record is created, but the payment remains pending. The warehouse should not dispatch merely because the order exists. Staff verify the payment state first. Once payment is confirmed, stock is allocated, the correct sizes are picked and the fulfilment process begins.

## Practical Activity
Draw an order-status workflow containing at least eight stages. Add one possible error at each stage and the control that should prevent or detect it.

## Knowledge Check
1. Why is order status different from payment status?
2. What should happen before an order is treated as paid?
3. Name three common order exceptions.
4. Why should status changes reflect real operational events?
5. What record helps staff trace an order consistently?

## Feedback / Explanation
1. Order status describes the transaction stage, while payment status describes the state of money collection.
2. Payment should be verified through the approved system or provider workflow.
3. Examples include failed payment, unavailable stock and incorrect address details.
4. Incorrect statuses can trigger wrong actions and mislead staff or customers.
5. A unique order number supports traceability.

## Key Takeaways
- An order is a workflow, not a single event.
- Payment, order and fulfilment statuses should not be confused.
- Status changes must reflect verified events.
- Exceptions should be recorded and escalated rather than guessed.
- Accurate order records support customer service, finance and fulfilment.
