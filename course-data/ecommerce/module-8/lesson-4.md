# E-commerce & Online Store
## Module 8: Practical Online Store Project
### Lesson 4: Build Store Structure, Policies & Trust Information

**Estimated study time:** 40–45 minutes

## Learning Outcomes
By the end of this lesson, you should be able to:
1. Build a logical customer-facing store structure.
2. Create essential policy and contact pages for the project.
3. Present supplier and transaction information clearly.
4. Apply basic accessibility and mobile-usability checks.
5. Review the store for trust, transparency and compliance readiness.

## Why This Lesson Matters
A practical store is not complete when products are uploaded. Customers also need navigation, contact information, delivery expectations, return information and transaction terms. These elements help customers understand who they are buying from and what will happen before and after purchase.

## Key Terms / Vocabulary
- **Information architecture** — The way store content and navigation are organised.
- **Policy page** — A page explaining an important business process or transaction condition.
- **Trust information** — Verifiable information that helps customers understand and evaluate the supplier.
- **Accessibility** — Designing content and functions so people with different abilities can use them.
- **Transaction disclosure** — Information made available so customers can understand important terms before ordering.

## Main Lesson Content
### 1. Build customer-oriented navigation
Create clear top-level navigation and logical categories. Customers should be able to reach products, contact information, delivery information and policies without searching through unrelated pages.

### 2. Create essential project pages
The capstone should include appropriate contact, delivery, returns/refunds, privacy and terms information. These pages should reflect the actual project processes rather than copying another store's policies without understanding them.

### 3. Include relevant online supplier information
For South African e-commerce, the project should reflect ECTA disclosure principles, including sufficient supplier and transaction information, access to terms, return/refund information and the customer's ability to review and correct the transaction before final order placement.

### 4. Build trust through accuracy
Trust should come from verifiable information, clear pricing, realistic delivery promises, consistent business identity and professional policies. Fake security badges, false testimonials or unsupported accreditation claims should not be used.

### 5. Check mobile usability and accessibility basics
Review navigation, text readability, link labels, form labels, image alternatives where appropriate, keyboard access to important functions and mobile layouts. Checkout and policy links should remain usable on small screens.

### 6. Test policy against operations
A policy is useful only if the business can follow it. If the project promises same-day customer responses or nationwide overnight delivery, the operational plan should support that promise.

## Worked Example / Demonstration

The return policy explains the project process in plain language, while the checkout lets the customer review quantities, address and total price before placing the final order.

## Practical Activity
Create the capstone navigation map and draft the essential policy pages. Then perform a trust audit checking supplier identity, contact routes, pricing, delivery, returns, privacy, transaction review and mobile usability.

## Knowledge Check
1. What is information architecture?
2. Why should policies match actual operations?
3. What should a customer be able to do before final order placement?
4. Why are fake trust badges poor practice?
5. Name two accessibility checks.

## Feedback / Explanation
1. The organisation of store information and navigation.
2. Customers rely on policies when making and resolving transactions.
3. Review the transaction and correct mistakes before ordering.
4. They create a misleading impression rather than genuine trust.
5. Examples include form labels, keyboard access, readable text or meaningful image alternatives.

## Key Takeaways
- A complete store includes information and policies as well as products.
- Navigation should follow customer needs.
- Policies should be accurate, understandable and operationally realistic.
- Trust should be based on verifiable information.
- Mobile usability and accessibility should be checked before launch.
