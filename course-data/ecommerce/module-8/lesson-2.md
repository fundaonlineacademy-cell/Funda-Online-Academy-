# E-commerce & Online Store
## Module 8: Practical Online Store Project
### Lesson 2: Build the Product Catalogue

**Estimated study time:** 40–45 minutes

## Learning Outcomes
By the end of this lesson, you should be able to:
1. Create a structured product catalogue for the capstone store.
2. Assign consistent SKUs, variants, attributes and specifications.
3. Write accurate product titles and descriptions.
4. Select appropriate product images and media.
5. Perform a pre-publication catalogue quality check.

## Why This Lesson Matters
The catalogue is the foundation of the practical store. If product data is incomplete, inconsistent or misleading, later work on pricing, merchandising, fulfilment and marketing will also be weak. The project should therefore demonstrate disciplined catalogue design rather than a collection of decorative product pages.

## Key Terms / Vocabulary
- **Catalogue structure** — The organised set of categories, product records and variants.
- **SKU pattern** — A consistent method for assigning internal product identifiers.
- **Variant matrix** — A record of sellable combinations such as size and colour.
- **Product data sheet** — The source record containing approved information for a product.
- **Catalogue QA** — Quality assurance used to verify accuracy, completeness and consistency.

## Main Lesson Content
### 1. Build from approved source information
For each project product, record the title, SKU, category, price placeholder, description, attributes, specifications, variants, stock quantity and delivery-relevant information. Even when products are fictional, the data should be internally consistent and realistic.

### 2. Use a consistent SKU system
Create a format that distinguishes every sellable variant. For example, a black medium hoodie could use `HD-BLK-M`. The exact pattern can differ, but duplicate or ambiguous SKUs should be avoided.

### 3. Write customer-focused listings
Titles should identify the product clearly. Descriptions should explain verified features, benefits, important limitations and specifications. Avoid unsupported claims such as “best quality guaranteed” unless the project can support them.

### 4. Use useful images
The project should show how customers would inspect the item online. Include clear primary images and relevant additional views. Variant images should match the selected option where practical. Any illustrative image should not create a false impression about what is included.

### 5. Apply category and filter logic
Group products according to customer understanding, not only internal codes. Attributes should use consistent terms so filters such as size, colour, material or price can work correctly.

### 6. Run catalogue QA
Before moving to pricing, check product titles, SKUs, variants, specifications, images, categories and stock values. Confirm that customer-facing information matches the project source data.

## Worked Example / Demonstration
StudyBox SA adds a “First-Year Starter Pack” containing notebooks, pens and highlighters. The main product receives a clear title, one SKU, verified contents, product images, weight and category. A backpack with three colours receives one main product record and separate SKUs for each colour variant.

## Practical Activity
Build at least 10 complete product records for the capstone store. Include at least one product with multiple variants. Create a catalogue QA checklist and record any corrections made before approval.

## Knowledge Check
1. Why should catalogue data come from an approved source?
2. What makes a SKU useful?
3. Why should variant values be consistent?
4. What should product images communicate?
5. What is the purpose of catalogue QA?

## Feedback / Explanation
1. It prevents contradictory or invented product information.
2. It uniquely and consistently identifies a sellable item.
3. Consistency supports filters, reporting and fulfilment.
4. The actual appearance and relevant details of the item.
5. To catch product-data errors before publication.

## Key Takeaways
- The project catalogue should be realistic, structured and internally consistent.
- Every sellable item or variant needs reliable identification.
- Titles, descriptions and images should support informed customer decisions.
- Categories and attributes should match customer browsing behaviour.
- Catalogue QA should happen before pricing and launch work continues.
