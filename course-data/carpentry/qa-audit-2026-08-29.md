**Date:** 2026-08-29
**Branch:** `carpentry-premium-course-build`

## Purpose
This audit verifies the learner-facing Carpentry content layer before learner-workspace and Supabase integration. It also records a correction to an earlier QA interpretation: GitHub compare statistics reported `0 additions` for several later files, but direct repository directory and file reads confirm those files contain substantive content. Compare line statistics must therefore not be used as the sole test for file completeness.

## Architecture verified

- Lessons 1–8: teaching lessons
- Entry 9: Formative Assessment
- Entry 10: Summative Assessment

Target course total: 80 teaching lessons + 10 formative assessments + 10 summative assessments = 100 learner entries.

## Content-standard checks for integration
Before production integration, the loader/rendering layer must preserve these academic controls:
1. Teaching lessons remain distinct from formal assessments.
2. Formative assessment must be passed before summative unlocks.
3. Formative delivery: 15 questions drawn from a 32-question bank, pass 70%, maximum 3 attempts.
4. Summative delivery: 25 questions drawn from a 52-question bank, pass 70%, maximum 3 attempts.
5. Answers must not be exposed before submission.
6. Attempts, selected questions, learner answers, score, percentage, outcome and timestamps must be persisted in the production assessment system.
7. Module progression and certification must use competency rules rather than a simple overall average that could hide a failed compulsory module.
8. Manufacturer, workplace, project and applicable legal requirements override generic instructional assumptions where relevant.

## QA conclusion
The earlier “empty Modules 6–10” finding was a compare-statistics false positive. Direct repository inspection confirms that the later modules are populated. The actual assessment-format defects found during direct QA have been corrected in Module 6 Formative and Module 10 Formative. The content layer is therefore suitable to proceed to integration QA, subject to frontend/backend implementation testing before any production release.
