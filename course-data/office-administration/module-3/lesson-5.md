# Office Administration Certificate: From Admin to PA
## Module 3: Documents, Filing & Records
### Lesson 5: Document Version Control & Naming Conventions

**Estimated study time:** 45 minutes

## Learning Outcomes
By the end of this lesson, you should be able to:
1. Explain why version control is necessary.
2. Distinguish working drafts from approved versions.
3. Apply a consistent version and filename convention.
4. Maintain a simple document change history where appropriate.
5. Prevent obsolete documents from being used accidentally.

## Why This Lesson Matters
Version confusion can create costly mistakes. A meeting pack may contain old figures, a procedure may contain an outdated approval limit, or a client may receive a draft that was never authorised. Version control answers a basic question: which copy should people trust?

## Key Terms / Vocabulary
- **Version** — A defined state of a document at a point in its development.
- **Revision** — A change made to a document.
- **Draft** — Work not yet formally approved for final use.
- **Approved version** — Version authorised for its intended official use.
- **Superseded** — Replaced by a newer authorised version.
- **Change history** — Record of significant revisions, dates and approvals.
- **Naming convention** — Standard rules used to name files consistently.

## Main Lesson Content
### 1. Why version control matters
When several copies exist, employees need to know which is current. Without control, obsolete information can re-enter workflows after corrections have already been made.

### 2. Draft status
Drafts may change frequently. Clearly identify them where confusion is possible. Avoid sending a draft outside its intended review group unless authorised and clearly understood.

### 3. Approved versions
Approval marks the version authorised for a defined purpose. After approval, material changes should follow the required review process rather than silently altering the official copy.

### 4. Version numbering
Organisations use different conventions. One simple method uses major versions for approved releases and minor identifiers for drafts, but learners must follow their organisation's actual rules. Consistency matters more than inventing a universal numbering scheme.

### 5. Filenames
Useful names might include subject, document type, date and version, for example `Supplier_Onboarding_Procedure_v2.0_2026-08-29.pdf` if that convention matches workplace standards.

Avoid names such as `final_FINAL_reallyfinal2.docx`.

### 6. Change histories
Controlled procedures and important documents may include a table recording version, date, change summary and approver. This helps users understand what changed and supports audits.

### 7. Superseded copies
When a new approved version is released, obsolete versions should be removed from active use or clearly archived/superseded according to procedure. Do not leave an old procedure in the same active folder without clear status.

### 8. Collaboration tools
Modern platforms may maintain automatic revision histories. These features improve traceability but do not replace approval status. The newest edit is not necessarily the approved version.

### 9. External distribution
When sending documents externally, verify the approved version and correct file. Consider a controlled final format where editing is not required. Record distribution where necessary.

### 10. Emergency corrections
If a serious error is found in an approved document, notify the owner promptly. Follow the correction and reapproval process. Do not allow a known material error to remain in circulation merely to preserve version numbering.

## Worked Example / Demonstration
A policy folder contains `Leave Policy final.docx`, `Leave Policy v3.docx` and `Leave Policy NEW.pdf`. Nobody knows which is approved. The administrator checks the authorised record, identifies the approved version, moves obsolete copies out of active use according to procedure, applies the naming convention and ensures future revisions follow documented approval.

## Practical Activity
Create a naming/version convention for a monthly management report that goes through two drafts and one approved release. Show filenames for all three stages. Then create a change-history table with columns for version, date, change, author and approver.

## Knowledge Check
1. What question should version control answer?
2. Why should drafts be identifiable?
3. Can an approved document be materially changed without appropriate review?
4. Is there one universal version-numbering convention every company must use?
5. Why are “finalfinal” filenames weak controls?
6. What does a change history record?
7. What should happen to superseded active copies?
8. Why does automatic revision history not replace approval?

## Key Takeaways
- Version control protects users from obsolete information.
- Draft, approved and superseded status should be clear.
- Use consistent naming and version rules.
- Change histories improve traceability for controlled documents.
- The newest file is not automatically the approved file.
