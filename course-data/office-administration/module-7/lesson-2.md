# Office Administration Certificate: From Admin to PA
## Module 7: Office Technology, Information & Confidentiality
### Lesson 2: Word-processing Standards & Document Production

**Estimated study time:** 45–50 minutes

## Learning Outcomes
By the end of this lesson, you should be able to:
1. Use word-processing tools to create structured professional documents.
2. Apply styles, templates, page controls and review features consistently.
3. Use comments and tracked changes appropriately during collaboration.
4. Prepare final documents without exposing unnecessary editing history.
5. Perform quality and accessibility checks before distribution.

## Why This Lesson Matters
Word-processing software can produce polished documents quickly, but poor use creates inconsistent formatting, hidden comments, broken page layouts and version confusion. Administrators need controlled document-production habits, not only typing ability.

## Key Terms / Vocabulary
- **Style** — Reusable formatting rule for headings, paragraphs or other document elements.
- **Track changes** — Feature recording edits for review.
- **Comment** — Reviewer note attached to document content.
- **Section break** — Document control separating areas with different layout settings.
- **Template** — Reusable approved document structure.
- **Document properties** — Metadata such as title, author or subject stored with a file.

## Main Lesson Content
### 1. Use templates and styles
Begin with the current approved template where available. Apply heading and paragraph styles instead of manually formatting each line. Styles improve consistency and support navigation.

### 2. Structure documents logically
Use headings, paragraphs, lists and tables according to the information. Avoid long unbroken text when readers need to scan for actions or sections.

### 3. Control pages properly
Use page and section breaks rather than repeated blank lines. Check headers, footers, page numbers and table splits before finalising.

### 4. Use tables deliberately
Tables are useful for schedules, responsibilities and comparisons. Keep headings clear and avoid overly complex nested layouts that become difficult to edit or read.

### 5. Collaborate with review features
Track changes can show what changed and comments can explain questions. Before final release, resolve comments and accept/reject changes according to the approval process rather than leaving internal discussion visible unintentionally.

### 6. Find and replace carefully
Bulk replacement saves time but can create errors if words appear in unexpected places. Review the results rather than assuming every replacement is correct.

### 7. Protect document integrity
Do not disable protection, editing restrictions or macros simply to make a task easier unless authorised and safe. Suspicious documents or unexpected security warnings should be escalated.

### 8. Accessibility and usability
Use meaningful headings, readable fonts, descriptive link text and appropriate alternative text for important images where organisational standards require it. Accessibility improves usability for many readers.

### 9. Finalisation
Check spelling, facts, formatting, hidden comments, recipients, document status and output format. If distributing PDF, review the converted file as well as the source document.

### 10. Store source and final versions correctly
Keep the authoritative editable source and approved final output in the approved locations. Do not let personal downloads become competing official copies.

## Worked Example / Demonstration
A policy document is ready for release, but tracked changes still show deleted confidential comments and the footer has an old effective date. The administrator resolves all review markup, confirms the current date/version, checks the PDF export and stores both the approved source and final copy in the controlled folder.

## Practical Activity
Create a two-page office procedure using an approved or simulated template. Use heading styles, one numbered procedure, one table and a footer. Add a sample tracked change and comment, then prepare the document for final release by resolving all review content and checking the PDF preview.

## Knowledge Check
1. Why are styles better than manual formatting for recurring document elements?
2. When should a section break be used?
3. What is the risk of leaving comments or tracked changes in a final document?
4. Why should bulk find-and-replace be reviewed?
5. What should happen with unexpected security warnings in a document?
6. Name two accessibility practices.
7. Why check a PDF after conversion?
8. Why should source and final copies be stored in controlled locations?

## Feedback / Explanation
1. They improve consistency, navigation and efficient document-wide changes.
2. When a section needs different page layout or formatting controls.
3. Internal discussion or deleted information may remain visible to recipients.
4. Replacement may affect unintended words or sections.
5. Follow authorised security/IT escalation rather than bypassing controls.
6. Examples include meaningful headings, readable text, descriptive links and alternative text.
7. Layout can change during conversion.
8. So the authoritative editable and approved released versions remain identifiable.

## Key Takeaways
- Word-processing skill includes structure, review control and finalisation.
- Use templates, styles and page controls consistently.
- Resolve review markup before final distribution.
- Accessibility and readability are part of professional quality.
- Store authoritative source and final versions correctly.
