# Office Administration Certificate: From Admin to PA
## Module 8: Practical Admin-to-PA Project
### Lesson 2: Build the Administrative Control System

**Estimated study time:** 60 minutes

## Learning Outcomes
By the end of this lesson, you should be able to:
1. Build a practical daily administrative control system.
2. Create task, follow-up and handover registers.
3. Prioritise simulated work and identify escalation triggers.
4. Link procedures and records to routine workflows.
5. Test the system using realistic office events.

## Project Task
Using the Ubuntu Business Services simulation, create the core control system that will manage daily administrative work throughout the capstone.

## Required Evidence
Create:
- **E01 — Daily Task Register** with Priority, Owner, Due Date, Status, Dependency and Follow-up fields;
- **E02 — Daily Opening/Closing Checklist**;
- **E03 — Administrative Handover Log**;
- **E04 — Escalation Guide** showing at least eight common issues and when they require manager/specialist input.

## Main Lesson Content
### 1. Capture work centrally
Create one authoritative task register for project actions. Avoid using memory or unrelated notes as the only control.

### 2. Use meaningful statuses
Use statuses such as Not Started, In Progress, Waiting, Blocked, Completed and Escalated. A status should help another person understand what is happening.

### 3. Define priority logic
Classify work based on impact, deadline, dependencies and authority. Do not mark every item urgent.

### 4. Add follow-up points
For waiting actions, set a follow-up date before the final deadline. This provides recovery time if information is missing.

### 5. Build escalation triggers
Examples include confidentiality incidents, safety concerns, significant customer complaints, material spending approvals, deadline conflicts and access exceptions.

### 6. Create daily controls
Opening controls should review systems, diary, expected visitors and handover. Closing controls should reconcile outstanding items, secure information and prepare the next handover.

### 7. Test the system
Enter at least ten events into the task register, including a delayed supplier response, urgent client request, missing meeting document and conflicting executive appointment.

### 8. Review usability
A good control system should allow another competent administrator to understand what is outstanding without needing your memory.

## Practical Activity
Complete E01–E04 and test them through one simulated workday. At the end of the day, identify three control weaknesses and improve the templates before marking them final.

## Knowledge Check
1. Why should project work use one authoritative task register?
2. What makes a status meaningful?
3. What factors should determine priority?
4. Why should follow-up occur before the final deadline?
5. Name three escalation triggers.
6. What belongs in opening controls?
7. What belongs in closing controls?
8. How can you test whether a handover is useful?

## Feedback / Explanation
1. It prevents actions from being fragmented across memory and unrelated notes.
2. It explains the actual work state or dependency.
3. Impact, deadline, dependencies and authority.
4. It leaves recovery time if input is missing or delayed.
5. Examples include safety, confidentiality, financial authority or major deadline conflicts.
6. Systems, diary, expected activity and prior handover.
7. Outstanding actions, security/records checks and next-shift handover.
8. Another competent person should be able to continue the work using it.

## Key Takeaways
- The control system is the backbone of the capstone.
- Use one visible task and follow-up method.
- Priority and escalation should be rule-based.
- Opening, closing and handover controls protect continuity.
